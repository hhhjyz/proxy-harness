# Internal v1 integration contract

This is a project implementation contract, not a personal assistant skill.

- Python 3.11+, package `proxy_harness`, root CLI `python -m proxy_harness`.
- Renderer: `render_scene(scene_path: Path, spec: dict, output_dir: Path, *, browser: str | None = None, backend: str = "swiftshader", video: bool = False) -> dict` in `proxy_harness/render.py`. It writes frames, manifests.json, contact_sheet.png, top_view.png, console.log, render_meta.json, l1_report.json; optional proxy.mp4. A failed render is a report, not fabricated success.
- Checker: `check_scene(spec: dict, manifests: list[dict], *, runtime_errors: list[str] = (), determinism: dict | None = None, source: str = "") -> dict` in `proxy_harness/checks.py`. Report contains schema_version, hard_pass, failures (list of {code,message,t?,subject?,...}), warnings, metrics. Determinism is {passed: bool, comparisons: list, tested_times: list}. Source lint checks capture contract only; every violation names a fix.
- Asset runtime `assets/runtime.js` imports `three` from a local pinned import map. Export `createHarness({scene,camera,renderer,update,subjects,seed})`; subjects = [{id, object, role?}]. It installs non-writable `window.renderAt(t)`, `window.exportManifest(t)`, `window.renderTopAt(t)`, `window.__harnessReady=true`. Update must set all state absolutely from t. Renderer calls capture with viewport from spec and canvas id="scene". Top-view method renders a temporary top camera without changing primary camera or update state. `window.__harnessMeta` exposes actual backend and Three revision.
- Manifest schema: {schema_version:"1.0",t,camera:{position:[x,y,z],quaternion:[x,y,z,w],forward:[x,y,z],pitch_deg,fov_deg,near,far},objects:[{id,role,world_aabb:{min:[x,y,z],max:[x,y,z]},frustum_intersects,in_front,fully_in_frame,projection_valid,projected_area_ratio,ndc_box:{min:[x,y],max:[x,y]},visible,collider:null|{type:"sphere",center:[x,y,z],radius,exact:true}|{type:"obb",center:[x,y,z],half_extents:[x,y,z],axes:[[x,y,z],[x,y,z],[x,y,z]],exact:true},primitive_count}],audit:{mesh_count,registered_mesh_count,unregistered_mesh_count,primitive_count}}. Runtime derives geometry; exact colliders only genuine sphere/box meshes without deformations, shear or nonuniform sphere scaling. Composite meshes use null collider; AABB overlap alone is warning. Ground/decoration can be registered as roles.
- Spec: {schema_version:"1.0",task_id,prompt,split:"train"|"dev"|"holdout"|"demo",seed:42,duration_s:3,fps:12,width:640,height:360,sample_times:[0,0.5,1,1.5,2,2.5,2.916667],subjects:[{id,role:"primary",required:true,fully_in_frame:true,min_area_ratio:0.005,max_area_ratio:0.7,active_intervals?:[[start,end]]}],camera:{pitch_deg_range?:[min,max],height_range?:[min,max]},collision:{forbidden_pairs:[[id,id]],allowed_pairs:[],tolerance:0.001},evaluation:{pass_score:75,hard_fail_score_cap:40}}. Defaults are examples not universal screen-size constraints. Spec dimensions even; sample t in [0,duration); schema and semantic checks required.
- Scene is a single editable scene.html plus appearance_prompt.txt. Local `runtime.js`, `primitives.js`, `vendor/three.module.js`, `vendor/three.core.js` resolved beside it; trusted assets copied by controller and hash checked after Coder. Runtime may add optional fields. Only 2 scene output files editable, coder worktree independent of run artifacts.
- Evaluation: fresh request each round. eval.json: {status:"evaluated"|"skipped"|"error",score:0..100|null,subject_complete:bool|null,issues:[{code,message,repair?}],summary:string}. Effective score capped by code for L1 fail, invalid/error/skipped never accepted. Model score doesn't override hard gates.
- root implements config CLI, CLI engine adapters, independent evaluator and orchestration. Single writer + bounded iterations + immutable snapshots + best valid preservation.
- `outerloop.py` and `devset/` own staged distillation/admission, accepts batch results {schema_version:"1.0",manifest_sha256,config_sha256,asset_sha256,condition_id,records:[{task_id,split,seed,spec_sha256,status:"accepted"|"rejected"|"error"|"unverified",hard_pass,subject_complete,score,code_lines,primitive_count,run_dir}]}.
- Distillation only split=train, no promotion without matching paired dev runs. Template output instructions may mention SKILL.md but do not install personal skills in this build. Reference knowledge in project docs, no unvalidated distilled assets shipped as proven skills.
- Source, rendered evidence and measured results are real. Demo/fixtures explicitly identify that no live model ran.
